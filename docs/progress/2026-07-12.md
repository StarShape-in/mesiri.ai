## 4. Auth & password features

- Added `PATCH /auth/me` (self profile update) and `POST /auth/change-password` (logged-in change); `getMe` now returns email + phone.
- **Password reset is operator-driven, not self-service** (no email provider): the "Forgot Password" page no longer fakes an email. Removed the orphaned self-service token flow cleanly.
- **Forgot-password now notifies staff**: `POST /auth/request-reset` creates a notification for **every active Admin + Operator** (reuses `createNotification`, so it also emits over the socket and shows in the Notifications page). Wired on:
  - **Mobile driver login** — "Can't log in? Notify my operator"
  - **Web forgot-password** — "Notify my operator"
- The actual reset is done by an operator/admin via User Management (web users) or the Drivers module (drivers) — `updateUser` already hashes a new password.

## 9. Ops actions taken

- ✅ **Rotated `JWT_SECRET`** (July 12, 2026). The old secret had been exposed in git history; it's now provided as a **GitHub Actions secret** and injected into the API container via `${JWT_SECRET}` in `docker-compose.yml` (no longer hardcoded anywhere). Rotating invalidates all previously-issued tokens, so every user re-logs in once — expected and fine.

  **Procedure (for future rotations):**
  1. Generate a new secret: `openssl rand -base64 48`
  2. Update it in the deploy env — GitHub → repo **Settings → Secrets and variables → Actions → `JWT_SECRET`** (or the runner's env), since `docker-compose.yml` reads `JWT_SECRET` from the environment.
  3. Redeploy (push to `main`, or on the VPS re-run `docker-compose up -d --build` so the API container picks up the new value).
  4. Confirm the API still logs in; all existing sessions are invalidated by design.
